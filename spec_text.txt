ต้องการสร้างระบบ EZY Pawnshop2006 Web  ในรูปแบบ PWA (Progressive web app) ที่มีความสามารถ ดังต่อไปนี้

ประกอบด้วย แฟ้มลูกค้า(Customer), แฟ้มรายการทรัพย์รับจำนำ (Ticket) , แฟ้มรับชำระเงิน(Payment), แฟ้มข้อมูลผู้ดูแลระบบ (User)   
แฟ้มลูกค้า มี field ดังนี้  เลขบัตรประชาชน(Id) , เบอร์โทรศัพท์(Tel) , ชื่อ –นามสกุล (Name)
แฟ้มรายการทรัพย์รับจำนำ มี field ดังนี้  
1- ชุดข้อมูล (SysemID) 1,2
2- ปีทำการ (BudYear) ปี พ.ศ. 2569
3- เล่มที่ตั๋วจำนำ (BookNo), 
4-เลขที่ตั๋วจำนำ (DocNo) 
5- สถานณะการชำระ(BillType) Blank = ยังไม่ชำระ 2=ชำระแล้ว 9=ยืนยันการชำระ
6- วันที่ชำระ(BillDate) yyyy/mm/dd hh:mm:ss
7- รหัสชำระ(BillNo) O260718-0001 ประกอบด้วย type “O” + left(year,2)+month+day + “-“ + ลำดับที่รายการ 4 หลัก ให้ไปดึงเลขที่นี้ที่แฟ้มชำระเงิน
8.-เล่มใบเสร็จ (BillBookNo)
9-เลขที่ใบเสร็จ (BillDocNo)
10- จำนวนเงินรับจำนำ (Asstotal)
11 จำนวนเงินชำระดอกเบี้ย (Totalint)
12- จำนวนเดือน (MonthTotal)
13-ดอกเบียต่อเดือน(MonthInt)
14-วันที่จำนำ (AppDate)  yyyy/mm/dd hh:mm:ss
15.วันครบกำหนด (ExpDate)  yyyy/mm/dd
16.รายการทรัพย์รับจำนำ (Model) ประกอบด้วย ชื่อสินค้า น้ำหนัก หรือ Serial No จำนวนชิ้น
17.สถานะการชำระ (BillStat) N = จำนำ  I=ส่งดอกสำเร็จแล้ว R=ไถ่ถอนสำเร็จ C=เพิ่มต้นสำเร็จ D=ลดต้นสำเร็จ
18.เลขบัตรประชาชน (Id)
-แฟ้มรับชำระเงิน(Payment) มี field ดังนี้
1.เลขที่รหัสชำระ(BillNo) O260718-0001 ประกอบด้วย type “O” + left(year,2)+month+day + “-“ + ลำดับที่รายการ 4 หลัก ให้ไปดึงเลขที่นี้ที่แฟ้มชำระเงิน  เพิ่มลำดับที่ +1 เมี่อมีการทำรายการอัตโนมัติ
2- ชุดข้อมูล (SysemID) 1,2
3- ปีทำการ (BudYear) ปี พ.ศ. 2569
4- เล่มที่ (BookNo), 
5-เลขที่ (DocNo) 
6- สถานณะการชำระ(BillType) Blank = ยังไม่ชำระ 2=ชำระแล้ว 9=ยืนยันการชำระ
7- วันที่ชำระ(BillDate) yyyy/mm/dd hh:mm:ss
8-สลิปการโอน (Slip) ไฟล์ภาพ
9.เลขบัตรประชาชน (Id)
แฟ้มข้อมูลผู้ดูแลระบบ (User) ประกอบด้วย field ดังนี้
1.รหัสพนักงาน  (UserID)

Web App แบ่งการทำงาน เป็น 2 หน้าที่หลัก  
1. Page สำหรับลูกค้าทั่วไป
2. Page สำหรับผู้ดูแลระบบ
โดยแยกหน้าที่กันก็ต่อเมื่อผุ้ใช้ Login แล้ว (ได้แนบไฟล์ภาพ Logo.ico ให้แล้ว โดยแปลงไฟล์นามสกุลให้พร้อมใช้กับ Web App)
กรณีลูกค้าทั่วไปใช้ กรอก เลขบัตรประชาชน กับ เบอร์โทร แล้วพบข้อมูลในแฟ้มลูกค้า (Customer) ก็ให้ไปที่ Page สำหรับลุกค้าทั่วไป แต่ถ้าไม่เจอข้อมูลในแฟ้มลูกค้า (customer)
ก็จะไปค้นหาในแฟ้มผู้ดูแลระบบ(user) โดยเลขบัตรประชาชน คือ รหัสพนักงาน(UserId) แทน เบอร์โทร เป็น Password
ถ้าพบข้อมูลก็ให้ไปที่ Page สำหรับผู้ดูแลระบบ ถ้าไม่เจอเลย ก็ให้แสดงข้อความเตือนว่า
